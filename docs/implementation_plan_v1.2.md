# 개발 구현 계획서 - v1.2 (검색 정확도 및 UI 개선)

## 1. 개선 배경 및 목표
사용자 피드백에 따라 기존 연/월 단위 검색에서 발생하는 **결과 불일치(API 검색 정렬 한계)** 및 **크롤링 속도 저하(댓글 수집 병목)** 문제를 해결하기 위해 시스템을 개편합니다.
특히 네이버 카페 게시물의 경우 Open API가 날짜 필터링과 정렬에 매우 취약하므로, 사용자가 브라우저에서 직접 검색하듯 **웹 검색(퍼피티어) 방식**으로 전환합니다.

## 2. 변경되는 아키텍처 (Tech Stack Updates)
- **블로그 포스트**: `Naver Open API` 유지 (100건 단위 빠른 조회 후 애플리케이션 메모리에서 날짜 필터링)
- **카페 포스트**: `Puppeteer` 웹 크롤링 전환
  - 대상 URL: `search.naver.com`의 **카페 탭** (`ssc=tab.cafe.all`)
  - 활용 기능: 네이버 통합검색의 브라우저 전용 **기간 상세검색 옵션**(`nso=p:fromYYYYMMDDtoYYYYMMDD`) 직접 주입
  - 이점: API의 한계를 극복하고 사용자가 실제 브라우저에서 보는 것과 동일하고 일관된 건수를 추출 가능
- **검색 속도 최적화**: 댓글 수집 기능 전면 제외. 오로지 '포스트(게시글) 건수'에 단일 집중하여 수집 속도를 1~3초 내외로 단축.

## 3. 세부 구현 계획 (Proposed Changes)

### 3.1. 프론트엔드 (UI & UX)
#### [MODIFY] `src/app/page.tsx`
- **조회 기간 UI 복구**: 연도/월(드롭다운) 방식에서 다시 **시작 연월일(Start Date) ~ 종료 연월일(End Date)** 입력 방식으로 교체.
- **결과 표출 변경**: 하단의 원문 데이터 엑셀 형식 표를 제거하고(다건 조회 속도 및 렌더 목적으로 생략), 화면 중앙에 **"총 블로그 포스트 건수"**와 **"총 카페 포스트 건수"**만 직관적이고 큼직하게 표출.

### 3.2. 백엔드 API 라우트
#### [MODIFY] `src/app/api/analyze/route.ts`
- 인입 파라미터를 `year, month`에서 `startDate, endDate` (예: 2026-02-01, 2026-02-27) 포맷으로 롤백.
- 댓글 관련 집계 로직(blogCommentCount, cafeCommentCount 등) 완전히 삭제.
- 응답 JSON에 `blogPostCount`, `cafePostCount`만 반환하도록 다이어트.

### 3.3. 크롤러 엔진 모듈
#### [MODIFY] `src/lib/crawler.ts`
- **블로그 수집기**: `fetchBlogPostsApi`를 활용해 API 호출 후 `startDate` ~ `endDate` 조건에 맞는 건만 필터링.
- **카페 수집기 (신규 작성)**: `Puppeteer`를 띄워 `https://search.naver.com/search.naver?ssc=tab.cafe.all&query=키워드&sm=tab_opt&nso=so:r,p:from시작일to종료일` 페이지 방문.
  - 퍼피티어를 통해 화면의 스크롤을 끝까지 내려 페이징된 모든 결과물 요소(`.title_area` 또는 `.bx`)의 렌더링 개수를 직접 카운팅.
  - 불필요한 이미지, CSS, 폰트 요청을 `setRequestInterception`으로 차단하여 퍼피티어 구동 속도 극대화.

## 4. 검증 계획 (Verification Plan)
### 수동 테스트
1. 기능 업데이트 이후 터미널에서 `npm run dev` 구동.
2. 브라우저에서 키워드 '깨봉수학'과 특정 기간(예: 2026년 2월 23일 ~ 27일)을 입력 후 검색 버튼 클릭.
3. 동일한 기간을 **3회 연속 조회** 구동.
4. **일관성 검증**: 3차례 모두 블로그 포스트 건수와 카페 게시물 건수가 1의 오차도 없이 **동일한 값**을 반환하는지 육안으로 확인.
5. 네이버 웹페이지에 직접 접속하여 동일 날짜/조건 검색 시 나오는 건수와 도출된 숫자가 유사한지 교차 검증.
